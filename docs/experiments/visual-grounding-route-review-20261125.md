## 2. 代码事实与不能过度推断之处

### 2.1 定位实际如何发生

实际分支 `oneref-ptp/models/OneRef_model.py:382–404`：

1. BEiT3 同时编码图像和表达，得到与查询相关的视觉 token。输入384、patch16，视觉网格24×24。
2. 视觉与文本分别线性映射并L2归一化；取文本开头聚合token与各视觉patch的点积作为余弦分数。
3. 对576个分数直接softmax，投影后的视觉token加权求和，变成768维向量。
4. 三层MLP＋sigmoid，输出归一化中心坐标和宽高。

官方在线文件核查位置340–358，Git blob SHA `6bbe08d2d1440d199c9c1e88b8cb3f28bbd9c2ea`。
来源：[官方代码](https://github.com/linhuixiao/OneRef/blob/master/models/OneRef_model.py#L340)。

这说明可以检验二维读出，但不证明空间信息已经消失：位置编码、上下文和全局信息仍可能存在于每个token内。不能把“求和”直接解释为失败原因。

### 2.2 余弦分数的标度值得诊断

这里用于patch汇聚的分数没有乘训练中的 `logit_scale`；后者用于另一个全局对比目标。理想余弦分数s∈[-1,1]，因此T=1时任意两patch的权重比不超过exp(2)≈7.389。

在N=576时，单patch权重上界为 `exp(2)/(575+exp(2))≈1.269%`；若目标只覆盖6个patch，即便这6个分数全为1，其余全为-1，总权重也至多约7.217%。这是数学边界，非实测响应图。特征值本身带有全局信息，因此这个边界不能证明性能上界。

固定温度/去padding仅作诊断对照，属于常规技术；不能把改温度写成创新。

### 2.3 原版已经有空间监督

`utils/loss_utils.py:219–228` 已经将框区域mask nearest下采样，与余弦分数计算Focal＋Dice。归档plain配置 `use_box_mask_constraints=true`，不是遗漏开关；`use_mask_loss=false` 则表示没有启用高分辨率分割分支。

同一余弦分数既作patch判别logit，又作softmax汇聚权重；有界logit的sigmoid落在约[0.269,0.731]。这是已核实的算子性质，尚未证明造成优化瓶颈。先测分布、梯度及改动后的独立验证，不直接给它定性为bug。

### 2.4 padding存在两处影响，不能混为一谈

`NormalizeAndPad` 生成像素padding mask；模型forward接收 `img_mask`，但没有用它屏蔽最后的patch汇聚。BEiT3联合编码时视觉padding位置也没有由这个mask传入，视觉部分encoder mask为全0。

先只改变末端汇聚，复用缓存即可。若改骨干attention mask，编码特征也随之变化，必须重跑encoder；不能用旧缓存宣称验证了该修改。边缘部分有效patch应按像素覆盖率计算，不能直接把非整块patch都当padding。

### 2.5 多层特征已有接口，但要核查层号和归一化

`Encoder.py:384–443` 能返回embedding及每层状态；最后 `encoder_out` 可能额外经final layer norm，因此不能把列表尾项与最终输出无条件视为同一种特征。缓存只保存预先选择的层，避免保存所有层的内存开销。

## 3. 现成结果提供什么证据

数据：10758个表达、1500张验证图像；单随机种子，事后诊断。原预测IoU按fp16官方评估计算重建，最大误差为0。

| 指标 | 普通OneRef | SADB＋局部竞争 |
|---|---:|---:|
| Acc@0.5 | 75.2649% | 75.0418% |
| Acc@0.75 | 56.6462% | 57.2783% |
| Acc@0.9 | 18.6373% | 19.6133% |
| 框平均IoU（逐表达重算） | 64.9632% | 65.1024% |
| 占补边输入面积1%–10%的表达数 | 4792 | 4792 |
| 该组Acc@0.5 | 67.7796% | 66.9866% |
| 占比≥10%的表达数 | 5966 | 5966 |
| 该组Acc@0.5 | 81.2772% | 81.5119% |

重要限制：面积是补边后输入面积，不是原图占比或COCO small定义。当前导出数据没有面积<1%的样本，不适合据此建立“极小目标”论文故事，其数据来源/过滤也尚未核实。分组差异受类别、场景、表达等混杂影响，不能当作尺度导致失败的因果证据。

普通基线2661个IoU<0.5失败中：671个在[0.3,0.5)，708个预测中心落在GT内部。两类可能重叠，不可相加。中心落在GT内也不证明选对对象。它们支持进一步检查边界读出，但不支持宣布主要失败都来自边界。

旧组合在高IoU阈值下略好，不应抹去；但它在主指标和较小面积组上未胜出，不能选择性改主指标宣布有效。完整诊断：`oss-results/long_comparison_20261125/localization_bottlenecks.json`。

## 5. 三条可实际执行的路线

### A：保留空间结构的轻量残差定位头——首选能力探针

问题：在已有的查询条件特征足够好时，是否还有定位信息未被单向量头利用？

首版结构刻意保持简单：

- 原始框分支保留作为比较起点。
- 最终视觉patch降到128维，恢复24×24网格，拼接有效区域比例及二维坐标通道。
- 一层depthwise 3×3＋pointwise卷积，按有效区域归一化地汇成4×4网格，再经小MLP输出4维坐标残差。
- 以 `sigmoid(logit(clamp(b0))+delta)` 得到cxcywh；最后残差层初始化为0，使初始输出等于原基线。
- 训练只用原有目标bbox，先L1＋GIoU；不引入真实实例mask，不加跨描述配对。

缓存能力探针中，骨干、相似度投影和visu_proj共同冻结；R0/R1/R2的原bbox MLP均从相同checkpoint开始并接受相同步数更新，R1/R2再分别加零初始化残差。记录各组实际可训练参数量；非空间残差MLP应匹配二维分支的参数规模。原框不detach，以免组间训练路径无意改变。

实现接入：`OneRef_model.py` 现有pred_box处增加可选readout；`engine.py`提供明确的缓存导出模式；新建独立轻量head模块。现有模型和已验证checkpoint不覆盖。

必要对照：原头等预算续训；相近参数量的非空间残差MLP。若只胜原头而不能胜非空间MLP，不能把增益归因于二维结构。上述卷积和残差都是常规设计，首版用于验证能力，不能直接当论文贡献。

如果探针通过，再研究“目标选择与边界范围的分开读出”：语义分支提供目标位置，几何分支在同一特征网格估计四条边界及范围。必须与直接四维回归、普通空间头对比，并进一步查核边界分布/解耦定位相关工作；当前新颖性未建立。不要一开始做复杂多模块系统。

失败条件：训练集拟合改善但独立图像验证不改善；只在已选难例上好；高IoU改善同时主指标明显退化；非空间MLP得到相同效果。出现这些情况就停止为该机制追加长训练。

### B：区分patch判别标度和定位汇聚——低成本诊断，创新优先级低

问题：同一有界余弦分数用于Focal/Dice和softmax汇聚，是否限制判别或目标区域权重？

先复用已有 `tools/rapid_pooling_probe.py` 的固定四种读出：baseline、valid_only、T=.5、T=.25。保持同一骨干和起始头；同时报告padding质量占比、熵、分数跨度与目标区域权重。GT只用于离线统计，不能参与推理权重生成。

若仅改变温度出现可重复信号，再把判别logit与汇聚logit的缩放分开训练，测回归与mask监督梯度是否冲突。不要自动引入LoRA、句法或多层融合。

失败条件：真实汇聚差异很小；头重适配后没有收益；效果由统一重训头即可解释。固定温度、mask和独立缩放最多作为控制/工程改进，不能单独作为核心创新。

### C：按定位质量选择局部细化——备选，需额外前向

问题：能否只给有希望修正的预测增加计算，而不是让所有图像重跑？

先用冻结模型做固定上下文裁剪再定位对照，保持全局表达不变；路由只能用预测框、可观察特征与在train训练的质量估计，不能用验证GT决定修哪些样本。检查目标越界、裁剪移除关系参照和错误自强化。

已有LFPR/C3VG覆盖较近。若要发展成方法，需要证明选择策略与额外计算分配有独立价值，并优于相同额外前向次数的随机或面积路由，报告准确率—延迟曲线。仅证明“多跑一次更准”不足以构成创新。

失败条件：额外前向后主指标不升；只能靠GT选择获益；推理增加与收益不合算；同预算简单路由同样有效。

## 6. 下一轮顺序与预算

1. 已完成：离线预测审计与代码/文献核查，无新GPU训练。
2. 缓存前先做32个样本计时、显存与输出复现，估算后再决定缓存规模。不能现在承诺具体完成时刻。
3. 首次筛选最多2048个训练表达＋1024个验证表达，以图像为单位隔离。由于既有骨干见过训练图像、旧checkpoint已用完整val选优，内部划分仍是探索性筛选，不称为全新独立测试。
4. 缓存最终视觉patch、文本聚合特征、valid覆盖率、原框与元信息；若只改末端头，冻结骨干可只编码一次。只存某一个温度下的聚合向量不足以训练新的空间头。训练和验证分别缓存，任何训练梯度不进入验证缓存。
5. FP16、768通道、576patch时，3072个表达的最终视觉特征约2.53GiB，另加文本、元信息；可分块加载。多层缓存成本成倍增加。本轮不默认多层全存。
6. 固定增广/样本顺序与相同更新预算。对照组：R0原头续训，R1非空间残差MLP，R2二维残差头；温度四方案按现有探针独立筛选，不与新头做笛卡尔积。
7. 第一轮总预算上限目标60 GPU分钟，含缓存；先计时，超预算缩小样本或中止。每个头上限10分钟；不因“还可能提升”无限延长。这是支出上限，非实测速度承诺。

预算执行时先预留缓存与复现20分钟、R0/R1/R2合计30分钟、诊断与余量10分钟；若缓存超过20分钟，本轮缩样或中止。温度先用同一缓存/原头做前向诊断，不再默认增加四组10分钟训练。温度导致的分布偏移需要等预算头重适配才能下最终结论，必要时占用后续一次限时筛选，而不是突破本轮总上限。
8. 晋级参考：R2相对R0/R1的Acc@0.5约+0.5pp以上，Acc@0.75方向一致，且图像成组重采样差值区间不跨0；小样本难以判定则标为不确定，可做一次预先限时的扩样确认，不因此直接进入整网长训练。+0.5pp是工程筛选阈值，不是发表门槛。
9. 有信号再做固定预算1–2小时的短程微调，与同起点plain对照，复核三个训练随机种子。若需改变编码器则缓存实验只作筛选、重新运行真正端到端实验。
10. 方法与超参数固定后，才做全数据及RefCOCO/+/g正式比较、消融、效率评估；testA/B留到最终确认，不能参与路由或模块选择。明确预训练、输入分辨率、真实mask/额外前景框等条件。

不能根据“训练loss下降、能过拟合、梯度非零”单独晋级。不能用oracle框/GT路由形成部署结果。不能因高IoU单项上涨就改写原先的主要成功标准。

## 7. 当前证据与下一步决定

已支持：现有主方案未胜普通基线；较小面积组和严格IoU仍有改善需求；代码提供明确的末端读出实验位置。
尚缺：真实patch分布、缓存导出复现、新头独立图像结果、跨种子效果、与直接先行方法的公式级查新。
决定：首轮只验证A的空间读出能力及B的常规诊断。C保留作备选。SADB/跨描述竞争不再默认叠加。没有证据支持时接受换方向，不能为已投入时间维持原故事。
